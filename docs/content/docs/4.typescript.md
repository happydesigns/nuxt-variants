Nuxt Variants generates a `CustomVariantRegistry` from the build-time registry
and Nuxt's merged `AppConfig`. Literal defaults are widened to primitive types
so the generated types stay ergonomic. A variant may therefore declare only
its name and inheritance in the registry while a layer or application defines
its complete config in `app.config.ts`.

## Generated Config Types

After `nuxt prepare` or `nuxt dev`, a literal variant name gives a typed config.

```ts
const { config } = useVariant("article");

config.value.copyButton;
config.value.surround;
```

Inherited fields are included in the resolved type.

For a reactive or otherwise dynamic variant name, the fallback config exposes
the union of fields from all known variants. If multiple variants define the
same field with different types, those types are unioned instead of collapsing
to `never`.

## `VariantConfigOf`

```ts
import type { VariantConfigOf } from "#nuxt-variants";

type ArticleConfig = VariantConfigOf<"article">;
```

`VariantName` is the generated union of all registered names. `useVariants()`
uses it for `name` and `extends`, and `useVariant().has()` offers those names as
editor suggestions while still accepting dynamic strings from routes or a CMS.

```ts
import type { VariantName } from "#nuxt-variants";

const fallback: VariantName = "content";
```

## Refine Inferred Types

Use `CustomVariantOverrides` only when normal inference cannot express a
deliberately narrower or library-owned contract. Empty registry config is not
a reason for an override: config declared in `app.config.ts` is inferred
automatically. Keep the declaration in a module by including `export {}`.

```ts [types/variants.d.ts]
import type { ButtonProps } from "@nuxt/ui";

export {};

declare module "#nuxt-variants" {
  interface CustomVariantOverrides {
    backButton: {
      backButton: Pick<ButtonProps, "icon" | "label" | "to">;
    };
  }
}
```

The refined `backButton` type also flows into variants that extend
`backButton`, such as `article`. Each override replaces the inferred config
type for that registry entry, so include every field the entry should expose.

This declaration affects TypeScript only. It does not validate or change the
runtime values supplied through `nuxt.config.ts` or `app.config.ts`. Prefer
ordinary inference; use an override only when an intentionally narrower
contract is more useful than the concrete value shape.
