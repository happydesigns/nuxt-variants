Nuxt Variants generates a `CustomVariantRegistry` from your registry and
app config. Literal values are widened to primitive types so the generated
types stay ergonomic.

## Generated Config Types

After `nuxt prepare` or `nuxt dev`, a literal variant name gives a typed config.

```ts
const { config } = useVariant("article");

config.value.copyButton;
config.value.surround;
```

Inherited fields are included in the resolved type.

For a reactive or otherwise dynamic variant name, the fallback config exposes
the union of fields from all known variants. If multiple variants define the
same field with different types, those types are unioned instead of collapsing
to `never`.

## `VariantConfigOf`

```ts
import type { VariantConfigOf } from "#nuxt-variants";

type ArticleConfig = VariantConfigOf<"article">;
```

## Refine Inferred Types

Use `CustomVariantOverrides` when an inferred value should have a narrower or
library-owned type. This example mirrors the back-button configuration used by
`@happydesigns/ui`. Keep the declaration in a module by including `export {}`.

```ts [types/variants.d.ts]
import type { ButtonProps } from "@nuxt/ui";

export {};

declare module "#nuxt-variants" {
  interface CustomVariantOverrides {
    backButton: {
      backButton: Pick<ButtonProps, "icon" | "label" | "to">;
    };
  }
}
```

The refined `backButton` type also flows into variants that extend
`backButton`, such as `article`. Each override replaces the inferred config
type for that registry entry, so include every field the entry should expose.

This declaration affects TypeScript only. It does not validate or change the
runtime values supplied through `nuxt.config.ts` or `app.config.ts`.
