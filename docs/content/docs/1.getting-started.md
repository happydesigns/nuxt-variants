Config Variants provides reactive config and feature checks to a Nuxt layout. This example uses two pages that share a layout. For plain TypeScript or Comark Content, start with the [integrations guide](/docs/platform-preview).

## Install

Install the published package in your Nuxt app.

```bash [Terminal]
pnpm add @happydesigns/config-variants
```

For an unpublished build, install the [local archive](/docs/platform-preview#build-the-local-package).

## Register the module and define variants

Use `@happydesigns/config-variants` in `modules`. Nuxt resolves the `/nuxt` entry automatically. A regular TypeScript import from the package root loads the portable resolver. The [API reference](/docs/api) lists the module options and Nuxt-specific imports.

Give both page variants a heading. Add a summary feature to the article. The layout reads both the active features and their merged configuration.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@happydesigns/config-variants'],
  variants: {
    registry: {
      heading: { config: { title: 'Notes' } },
      summary: { config: { summaryLabel: 'Overview' } },
      article: { extends: ['heading', 'summary'] },
      snippet: { extends: 'heading' },
    },
  },
})
```

## Select a variant per page

::code-group

```vue [app/pages/article.vue]
<script setup lang="ts">
definePageMeta({ variant: 'article' })
</script>

<template>
  <p>A note about the latest release.</p>
</template>
```

```vue [app/pages/snippet.vue]
<script setup lang="ts">
definePageMeta({ variant: 'snippet' })
</script>

<template>
  <p>Release checklist.</p>
</template>
```

::

## Render the layout

```vue [app/layouts/default.vue]
<script setup lang="ts">
const route = useRoute()
const { config, has } = useVariant(() => route.meta.variant ?? 'snippet')
const showSummary = has('summary')
</script>

<template>
  <main>
    <h1>{{ config.title }}</h1>
    <h2 v-if="showSummary">{{ config.summaryLabel }}</h2>
    <slot />
  </main>
</template>
```

Render the pages through the layout in `app/app.vue`.

```vue [app/app.vue]
<template>
  <NuxtLayout>
    <NuxtPage />
  </NuxtLayout>
</template>
```

Start Nuxt and open `/article` and `/snippet`. Both pages show **Notes**. Only the article shows **Overview**.

## Supply application defaults

An application or layer can override the heading for both pages in one place.

```ts [app/app.config.ts]
export default defineAppConfig({
  variants: {
    heading: { config: { title: 'Engineering notes' } },
  },
})
```

Register names and inheritance in `nuxt.config.ts`. App config can change values and activation for registered names. Restart Nuxt or run `pnpm exec nuxt prepare` after a structural change so the generated types are current. See [inheritance and precedence](/docs/concepts) and the [Nuxt API reference](/docs/api).
