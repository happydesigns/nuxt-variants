description: Replace implicit schema graph state and adopt the stricter schema contract.

Version 0.1 removes the process-global fallback used by the package-level
schema helper. Runtime variant resolution remains compatible.

## Share the Registry

Move the registry from an inline `nuxt.config.ts` object to a regular module:

```ts [variants.ts]
export const variantRegistry = {
  header: {},
  toc: {},
  article: { extends: ["header", "toc"] },
};
```

Use it from both configuration files:

```ts [nuxt.config.ts]
import { variantRegistry } from "./variants";

export default defineNuxtConfig({
  variants: { registry: variantRegistry },
});
```

```ts [content.config.ts]
import {
  createVariantSchemaResolver,
} from "@happydesigns/nuxt-variants/schemas";
import { variantRegistry } from "./variants";

const resolveVariantSchema = createVariantSchemaResolver(
  variantRegistry,
  variantSchemas,
);
const schema = resolveVariantSchema(["article"]);
```

## Review Schema Registries

The resolver now rejects:

- active variant names that are absent from the graph;
- schema keys that are absent from the graph;
- mixed Zod and Valibot registries;
- entirely empty registries without an explicit validator adapter.

When a known variant has no reachable schema, the resolver returns a real empty
object schema for the detected validator rather than a plain JavaScript object.

## Optional Runtime Adoption

`useVariant()` now also returns `features`, a computed readonly set. Existing
`config` and `has()` usage continues to work. Dynamic config fallback types now
union conflicting field types, and generated module-registry array types retain
their inferred element types.
