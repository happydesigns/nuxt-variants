## Feature Variants And Collection Variants

Real projects usually split variants into small feature names and larger
collection names.

```ts [nuxt.config.ts]
registry: {
  dates: { config: {} },
  authors: { config: {} },
  category: { config: {} },
  header: { config: {} },
  toc: { config: {} },
  article: {
    extends: ["dates", "authors", "category", "header", "toc"],
    config: {},
  },
  event: {
    extends: ["dates", "category", "header"],
    config: {},
  },
}
```

## Feature-Gated Layout

Use `has()` for inherited feature presence instead of checking config keys
directly.

```vue [layouts/article.vue]
<script setup lang="ts">
const collection = "article";
const { config, has } = useVariant(collection);
</script>

<template>
  <ArticleHeader v-if="has('header')" :config="config" />
  <ArticleToc v-if="has('toc')" :config="config" />
  <ContentRenderer />
</template>
```

## Runtime Editorial Override

Use `app.config.ts` to tune a variant without changing the build-time default.

```ts [app.config.ts]
export default defineAppConfig({
  variants: {
    article: {
      config: {
        backButton: { label: "All articles" },
        list: { limit: 12 },
      },
    },
  },
});
```

## Related UI Slot Overrides

`nuxt-variants` handles semantic config and schema composition. Slot class
composition is a separate concern that belongs in Nuxt UI, component props, or
utilities such as `tailwind-variants`.
