Replace `@happydesigns/nuxt-variants` with `@happydesigns/config-variants`
when migrating to 0.3. The new package contains the Nuxt module, standalone
resolver and integrations. Follow the [Nuxt quickstart](/docs/getting-started)
to install the local archive.

| In 0.2 | In 0.3 |
| --- | --- |
| `@happydesigns/nuxt-variants` in `modules` | `@happydesigns/config-variants` |
| `@happydesigns/nuxt-variants/schemas` | `@happydesigns/config-variants/schemas` |
| Types imported from `@happydesigns/nuxt-variants` | `@happydesigns/config-variants/nuxt` |

You can keep your `variants` options, `app.config` overrides, `useVariant()`
and `useVariants()` calls, and `#nuxt-variants` type imports.
Nuxt resolves the `/nuxt` entry when the package name appears in `modules`.

## Parent precedence

When two parents inherit the same base, the later parent’s resolved
configuration takes precedence. For example, suppose `left` overrides
`base.title`, while `right` inherits `base.title` unchanged. A variant
with `extends: ['left', 'right']` now resolves the title supplied through
`right`. In 0.2.0 it resolved the title supplied by `left`.

If your app has this shape, compare the affected values before upgrading.
Put the intended value on the child when it should win regardless of
parent order. The Inspector’s **Composition** and **Fields** sections
show which variant supplied each value.

Also compare fields that switch between a scalar and an object along the
graph. Each parent now resolves its own object before the child combines its
parents. A field from an earlier parent's object can survive that merge.

## Stored progress

Apps that derive a browser storage key from variant config should keep the
effective prefix and the production origin during a version swap. The
Course pilot exercised the Group ID checkpoint on the same origin in both
directions. Changing the prefix deliberately starts using a different set
of keys.

## Comark Content

Use the optional [Comark Content adapter](/docs/platform-preview#comark-content)
to validate and store the selected name on the document. Resolve effective
features and config through your current app when you render the document.
Existing records can use a registered default while you migrate their
frontmatter.

The local playground’s **Editorial documents** route shows this with
`article` and `event`. Each Markdown file selects its variant and the
Nuxt page displays the resulting features.

Use [typed groups](/docs/platform-preview#limit-a-content-source-to-a-variant-group)
when a source accepts only a subset of the registry. The
[Nuxt page example](/docs/platform-preview#limit-nuxt-pages-to-a-variant-group)
uses the same group mechanism for `definePageMeta`.
