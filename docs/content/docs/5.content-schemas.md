Use `@happydesigns/composable-variants/schemas` to let a Nuxt Content v3
collection inherit fields from the same variant graph as your layouts.
For Comark Content, see the [Comark Content adapter](/docs/platform-preview#comark-content).

## Zod Example

Define the article's feature inheritance in a shared registry.

```ts [variants.ts]
import { defineVariantRegistry } from "@happydesigns/composable-variants";

export const variantRegistry = defineVariantRegistry({
  dates: {},
  authors: {},
  header: {},
  toc: {},
  article: { extends: ["dates", "authors", "header", "toc"] },
});
```

Install Nuxt Content v3 and the Zod peer in the same app. Follow the
[Nuxt Content installation guide](https://content.nuxt.com/docs/getting-started/installation)
for its database setup. Register both modules in `nuxt.config.ts`.

```ts [nuxt.config.ts]
import { variantRegistry } from "./variants";

export default defineNuxtConfig({
  modules: ["@happydesigns/composable-variants", "@nuxt/content"],
  variants: { registry: variantRegistry },
});
```

```ts [content.config.ts]
import { defineCollection, defineContentConfig } from "@nuxt/content";
import { z } from "zod";
import {
  createVariantSchemaResolver,
  type SchemaRegistry,
} from "@happydesigns/composable-variants/schemas";
import { variantRegistry } from "./variants";

const variantSchemas: SchemaRegistry = {
  dates: z.object({
    date: z.date().optional(),
  }),
  authors: z.object({
    authors: z.array(z.string()).optional(),
  }),
  header: z.object({
    header: z.object({ title: z.string() }).optional(),
  }),
  toc: z.object({ toc: z.boolean().default(true) }),
};
const resolveVariantSchema = createVariantSchemaResolver(
  variantRegistry,
  variantSchemas,
);

export default defineContentConfig({
  collections: {
    blog: defineCollection({
      type: "page",
      source: "blog/**",
      schema: resolveVariantSchema(["article"]),
    }),
  },
});
```

Use `createVariantSchemaResolver` with the shared registry in
`content.config.ts`. It creates the explicit graph once without global state.

Install the optional Zod or Valibot peer used by your collection. The helper
composes object fields into a new schema. If your domain depends on strict
unknown-field rejection, a discriminated union or object-level refinements,
validate the input record with its original domain schema first. For example,
a composed Zod schema can strip an unexpected key that a strict source
object would reject.

Keep the registry in a shared `variants.ts` module and pass the exact same
object to `variants.registry` in `nuxt.config.ts`. This keeps schema inheritance
and runtime inheritance aligned without global state.

::caution
Do not mix Zod and Valibot schemas in the same `mergeVariantSchemas` call.
::

::warning
Unknown active variants and schema registry keys are configuration errors and
throw during startup. An entirely empty schema registry also needs an explicit
`zodAdapter` or `valibotAdapter` option.
::
