Nuxt Content v3 can infer SQLite columns from collection schemas.
`mergeVariantSchemas` lets a collection inherit schema fields from the same
feature graph that drives your layouts.

## Zod Example

```ts [content.config.ts]
import { defineCollection } from "@nuxt/content";
import { z } from "zod";
import {
  createVariantGraph,
  mergeVariantSchemas,
  type SchemaRegistry,
} from "@happydesigns/nuxt-variants/schemas";
import { variantRegistry } from "./variants";

const variantSchemas: SchemaRegistry = {
  seo: z.object({
    seoTitle: z.string().optional(),
    seoDescription: z.string().optional(),
  }),
  article: z.object({
    authorName: z.string(),
    authorUrl: z.string().url().optional(),
  }),
};
const variantGraph = createVariantGraph(variantRegistry);

export const collections = {
  blog: defineCollection({
    type: "page",
    source: "blog/**",
    schema: mergeVariantSchemas(["article"], variantSchemas, variantGraph),
  }),
};
```

Use `@happydesigns/nuxt-variants/schemas` with an explicit graph in
`content.config.ts`. The `#variants-schemas` virtual module is generated for
Nuxt/Vite runtime imports, but `content.config.ts` can execute before Vite
aliases are fully available.

Keep the registry in a shared `variants.ts` module and pass the exact same
object to `variants.registry` in `nuxt.config.ts`. This keeps schema inheritance
and runtime inheritance aligned without global state.

::caution
Do not mix Zod and Valibot schemas in the same `mergeVariantSchemas` call.
::

::warning
Unknown active variants and schema registry keys are configuration errors and
throw during startup. An entirely empty schema registry also needs an explicit
`zodAdapter` or `valibotAdapter` option.
::
