## Module Options

::field-group
::field{name="registry" type="Record<string, VariantDefinition>"}
Build-time variant definitions. Defaults to an empty object.
::

::field{name="configKey" type="string"}
Key used in `app.config` for runtime overrides. Defaults to `variants`.
::
::

## `useVariant(name)`

Resolves one variant and returns its merged config plus a feature inheritance
checker.

```ts
const { config, features, has } = useVariant("article");
const hasHero = has("hero");
```

`features` contains the selected active variant and its complete active
inheritance chain. `has()` reuses that resolved set.

## `useVariants()`

Returns a computed list of variants from both `nuxt.config` and `app.config`.

```ts
const variants = useVariants();
```

Each entry has:

```ts
interface VariantEntry {
  name: string;
  extends: string[];
  configKeys: string[];
}
```

`active: false` variants return empty config and do not match `has()` checks.

## `createVariantGraph(registry)`

Creates an explicit inheritance graph from the same registry object passed to
the Nuxt module. Keep that registry in a shared TypeScript file when Content
schemas also need it.

## `mergeVariantSchemas(activeVariants, registry, graph, options?)`

Merges Nuxt Content schemas for the active variants and their inherited
features.

```ts [content.config.ts]
import { defineCollection } from "@nuxt/content";
import { z } from "zod";
import {
  createVariantGraph,
  mergeVariantSchemas,
  type SchemaRegistry,
} from "@happydesigns/nuxt-variants/schemas";
import { variantRegistry } from "./variants";

const variantSchemas: SchemaRegistry = {
  seo: z.object({ seoTitle: z.string() }),
  article: z.object({ authorName: z.string() }),
};
const variantGraph = createVariantGraph(variantRegistry);

export const collections = {
  blog: defineCollection({
    type: "page",
    source: "blog/**",
    schema: mergeVariantSchemas(["article"], variantSchemas, variantGraph),
  }),
};
```

All schemas in one registry must use the same validator library. Unknown active
variants and unknown schema registry keys throw. For an entirely empty schema
registry, pass `{ adapter: zodAdapter }` or `{ adapter: valibotAdapter }` as the
fourth argument so the helper can return a valid empty object schema.

## Virtual Modules

### `#nuxt-variants`

Generated type module for `CustomVariantRegistry` and `VariantConfigOf`.

```ts
import type { VariantConfigOf } from "#nuxt-variants";
type ArticleConfig = VariantConfigOf<"article">;
```

### `#variants-graph`

Build-time inheritance graph and diagnostics.

```ts
import { variantDiagnostics, variantGraph } from "#variants-graph";
```

### `#variants-schemas`

Nuxt-generated schema helper entry that is aware of the current variant graph.
Use this virtual module only inside Nuxt/Vite runtime code. `content.config.ts`
is loaded before Vite aliases are guaranteed, so use the package export with
an explicit graph there:

```ts
import { mergeVariantSchemas } from "@happydesigns/nuxt-variants/schemas";
```

## Nuxt DevTools

In Nuxt dev mode, the module registers a `Nuxt Variants` DevTools tab. It shows
the variant list, inheritance graph, active features, base and app config
layers, resolved config, and diagnostics.

The inspector route is internal development tooling and is only registered in
Nuxt dev and test environments.
