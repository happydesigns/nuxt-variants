## Module Options

Register `@happydesigns/composable-variants` in `nuxt.config.ts` under
`modules`. Nuxt resolves its `/nuxt` entry. Use
`@happydesigns/composable-variants/nuxt` for explicit module or Nuxt type
imports.

::field-group
::field{name="registry" type="VariantRegistryInput"}
Build-time variant definitions. Entries accept an object or an array of
parent names. Defaults to an empty object.
::

::field{name="configKey" type="string"}
Key used in `app.config` for runtime overrides. Defaults to `variants`.
::

::field{name="devtools" type="'legacy' | 'devframe'"}
Defaults to `legacy`. Set `devframe` to use the native Nuxt DevTools v4 dock
with the optional DevFrame peer. See the [DevTools setup](/docs/platform-preview#devframe-and-nuxt-devtools).
::
::

## `useVariant(name)`

Resolves one variant and returns its merged config plus a feature-presence
checker.

```ts
const { config, features, has } = useVariant("article");
const hasToc = has("toc");
```

`features` contains the selected active variant and its complete active
inheritance chain. `has()` reuses that resolved set, so it matches both the
selected variant itself and inherited features. A variant with `active: false`
resolves to empty config and matches no features.

## `useVariants()`

Returns a computed list of variants registered through `nuxt.config`. Runtime
overrides contribute config keys but cannot introduce additional entries.

```ts
const variants = useVariants();
```

Each entry has:

```ts
interface VariantEntry {
  name: VariantName;
  extends: VariantName[];
  configKeys: string[];
}
```

## `defineVariantRegistry(registry)`

Defines a shared registry while preserving literal variant names, parent tuples,
and config values. Use it when the same registry is imported by
`nuxt.config.ts` and `content.config.ts`.

```ts [variants.ts]
import { defineVariantRegistry } from "@happydesigns/composable-variants";

export const variantRegistry = defineVariantRegistry({
  header: {},
  article: { extends: ["header"] },
});
```

## `createVariantGraph(registry)`

Creates an explicit inheritance graph from the same registry object passed to
the Nuxt module. Keep that registry in a shared TypeScript file when Content
schemas also need it. The returned `VariantGraph` is typed as immutable
build-time data.

## `createVariantSchemaResolver(registry, schemas, options?)`

Creates the recommended Nuxt Content schema resolver. It builds the explicit
inheritance graph once and returns a function that only needs the active
variants for each collection.

## `mergeVariantSchemas(activeVariants, registry, graph, options?)`

Merges Nuxt Content schemas for the active variants and their inherited
features. Use it when you already have an explicit variant graph.
Both helpers are exported from `/schemas`. The [Nuxt Content v3 schema guide](/docs/content-schemas)
shows a complete collection setup.

All schemas in one registry must use the same validator library. Unknown active
variants and unknown schema registry keys throw. For an entirely empty schema
registry, pass `{ adapter: zodAdapter }` or `{ adapter: valibotAdapter }` as the
resolver option so the helper can return a valid empty object schema.

## Virtual Modules

### `#nuxt-variants`

Generated type module for `CustomVariantRegistry`, `CustomVariantOverrides`,
`VariantName`, `VariantNameInput`, and `VariantConfigOf`.

```ts
import type { VariantConfigOf } from "#nuxt-variants";
type ArticleConfig = VariantConfigOf<"article">;
```

### `#variants-graph`

Build-time inheritance graph and diagnostics.

```ts
import { variantDiagnostics, variantGraph } from "#variants-graph";
```

Both exports are readonly. Import `VariantGraph` and `VariantDiagnostic` from
`@happydesigns/composable-variants/nuxt` when another integration needs their types.

Stable error diagnostic codes:

| Code | Meaning |
| --- | --- |
| `invalid-registry-entry` | A build-time entry is neither an object nor an array of parent names. |
| `invalid-runtime-entry` | An app-config override is not an object. |
| `invalid-extends` | A build-time `extends` value contains something other than parent names. |
| `invalid-active` | An `active` value is not a boolean. |
| `invalid-config` | A `config` value is not an object. |
| `unknown-registry-field` | A build-time entry contains a field other than `extends`, `active`, or `config`. |
| `unknown-runtime-field` | An app-config override contains a field other than `active`, `config`, or the separately diagnosed `extends`. |
| `unknown-parent` | A registry entry extends a name that is not registered. |
| `circular-extends` | The inheritance graph contains a cycle. |
| `runtime-extends` | App config attempts to change structural inheritance. |
| `unknown-runtime-override` | App config attempts to add an unregistered variant. |

## Nuxt DevTools

In Nuxt dev mode, the module registers a `Composable Variants` DevTools tab. It shows
the current route variant, searchable variant list, parents-first resolution
order, activity, Nuxt layer provenance, raw inputs, and resolved config. Its
refresh action re-reads current `app.config` overrides.

The inspector route is internal development tooling and is only registered in
Nuxt dev and test environments.
